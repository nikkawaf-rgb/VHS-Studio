# Устройство проекта

Коротко: как разложен код и почему именно так.

## Структура

```
VHS Studio/
├── vhs_studio/            пакет
│   ├── __init__.py        версия и публичный API пакета
│   ├── __main__.py        запуск: python -m vhs_studio
│   ├── config.py          константы, настройки по умолчанию, тексты описаний
│   ├── device.py          поиск ffmpeg, перечисление устройств, проба входов
│   ├── commands.py        сборка командной строки ffmpeg (фильтры, кодеки)
│   ├── estimates.py       оценка размера файла, форматирование чисел
│   ├── capture.py         Preview, Recorder, AudioMonitor — процессы и потоки
│   ├── ui.py              App: состояние, захват, настройки
│   └── ui_panels.py       панели: устройство, запись, обработка, предпросмотр
├── tests/                 юнит-тесты (unittest, без железа)
├── docs/                  скриншоты и эта документация
├── VHS Studio.bat         запуск без консоли
├── README.md              что это и как пользоваться
├── CHANGELOG.md           история изменений
└── .gitignore
```

## Направление зависимостей

```
config  ←  estimates  ←  commands  ←  capture  ←  ui
   ↑                         ↑
   └──────  device  ────────┘
```

Стрелка значит «импортирует». Циклов нет: `config` не знает ни о ком,
`ui` знает обо всех. Любой модуль ниже можно тестировать без окна.

## Что где лежит и почему

**`config.py`** — единственное место, где живут числа и тексты: диапазоны CRF,
описания кодеков, набор «рекомендуемых» настроек, пути к `settings.json`
и профилям. Поменять умолчания можно, не трогая логику.

**`device.py`** — всё общение с железом до старта захвата: найти `ffmpeg`
и `ffplay`, перечислить устройства DirectShow, определить, на каком пине
кроссбара висит сигнал. Функции не хранят состояния, их удобно вызывать
из тестов и из консоли.

**`commands.py`** — чистая функция «настройки → список аргументов ffmpeg».
Никаких процессов: на входе словарь настроек, на выходе массив строк.
Именно поэтому фильтры и кодеки можно проверять без камеры.

**`capture.py`** — три класса, каждый владеет одним процессом `ffmpeg`:

| Класс | Процесс | Задача |
|---|---|---|
| `Preview` | ffmpeg → `pipe:1` (rgb24), `pipe:2` (pcm) | картинка и уровень звука |
| `Recorder` | ffmpeg → файл + те же два потока | запись |
| `AudioMonitor` | ffplay | звук в колонки |

Общее у них: запуск, чтение потоков в отдельных потоках, аккуратная остановка
через `q` в stdin, чтобы контейнер дописался.

**`ui.py`** — `App`: что происходит сейчас (предпросмотр, запись), реакции на
кнопки, хранение настроек, склейка панелей. Работа с процессами идёт через
`capture`, поэтому UI не знает про аргументы ffmpeg. Обновление экрана идёт по
таймеру `after(12)`, кадры забираются из очереди — так проще не блокировать
главный поток.

**`ui_panels.py`** — четыре независимых виджета:

| Панель | Что содержит | Свои методы |
|---|---|---|
| `DevicePanel` | устройства, вход, стандарт | `collect(s)`, `apply(s)` |
| `RecordPanel` | кодек, CRF, звук, папка, имя | `collect(s)`, `apply(s)` |
| `FilterPanel` | деинтерлейс, шумодав, цвет, обрезка | `collect(s)`, `apply(s)` |
| `PreviewPane` | картинка, уровень, кнопки, статус | — |

Каждая панель умеет отдать свои значения в общий словарь настроек и принять
их обратно. `App` не знает, какие там ползунки, — только «собери настройки»
и «примени настройки». Добавить новую настройку = одна панель + ключ в
`DEFAULTS`.

## Потоки данных

```
камера → ffmpeg ─┬─ pipe:1 (rgb24) ─→ поток чтения → очередь → отрисовка
                 ├─ pipe:2 (pcm)   ─→ поток чтения → уровень + ffplay
                 └─ файл            (при записи)
```

Очередь кадров ограничена двумя элементами: если интерфейс не успевает,
старые кадры выбрасываются, а не копятся. Это то, что защищает от
«слайд-шоу с нарастающим отставанием».

## Почему один файл был проблемой

Исходная версия — 1731 строка в одном файле. Работало, но:

- нельзя было проверить сборку команды ffmpeg, не поднимая окно;
- любое изменение настроек интерфейса грозило задеть логику захвата;
- новому человеку трудно найти, где что.

Теперь `commands.py` и `estimates.py` — чистые функции без побочных эффектов,
их можно покрыть тестами без железа.

## Тесты

```bash
python -m unittest discover -s tests
```

42 проверки, железо не нужно: сборка фильтров и кодеков, оценка размера,
согласованность констант (у каждого кодека есть описание, диапазоны CRF
покрывают значения по умолчанию, «рекомендуемые» настройки существуют).
Запускаются за доли секунды, поэтому их удобно гонять после каждой правки.

## Что можно улучшить дальше

- Тесты на `ui_panels`: сейчас проверяется логика, а не виджеты.
- Вынести тексты интерфейса в файл локализации (сейчас русский зашит).
- Профили кассет можно хранить рядом с записями, а не в папке программы.
